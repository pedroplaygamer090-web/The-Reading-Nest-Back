# Code Review — The Reading Nest Backend

Este documento lista os achados do code review e diretrizes de qualidade que devem ser observados e corrigidos no projeto **The Reading Nest**.

---

## 🔴 Bugs / Problemas que causam comportamento errado

| Ref | Arquivo                         | Problema                                                                                                                                                                                                                                   | Impacto                                                                                                            | Ação Proposta                                                                                                             |
|-----|---------------------------------|--------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------|--------------------------------------------------------------------------------------------------------------------|---------------------------------------------------------------------------------------------------------------------------|
| B1  | `Usuario` e `UsuarioRepository` | O campo `senha` não é trazido pelas queries SQL de leitura (o que é correto), mas a Entity `Usuario` possui o getter/componente da senha. Resultado: a senha é serializada como `null` e vaza estruturalmente nas respostas de API. | Confusão e vazamento estrutural, poluindo payload e gerando alertas de segurança visual.                           | Adicionar `@JsonIgnore` (`tools.jackson.annotation.JsonIgnore`) no campo `senha` da Entity e usar `UsuarioResponseDTO`.    |
| B2  | `AluguelRepository`             | Uso de strings literais ou acentuadas nas consultas SQL de filtro (ex: `status NOT IN ('CONCLUÍDO')`). Dependendo do Collation (UTF-8) do MySQL configurado, strings acentuadas podem causar falha silenciosa na filtragem.               | O filtro de aluguéis não concluídos pode falhar em ambientes com collations diferentes ou encoding divergente.     | Usar enumeradores no Java (`StatusAluguel`) e padronizar valores sem acento no banco (`ativo`, `concluido`, `atrasado`).     |
| B3  | `AluguelService`                | Decrementar `quantidade_disponivel` no Java antes de salvar sem trava atômica no SQL (`UPDATE livros SET quantidade_disponivel = quantidade_disponivel - 1 WHERE id = ? AND quantidade_disponivel > 0`).                               | Em requisições simultâneas para a última cópia de um livro, o estoque pode ficar negativo (`-1`).                  | Realizar o decremento diretamente via `UPDATE` condicional no `JdbcTemplate` e validar se `rowsAffected == 1`.            |
| B4  | `GeneroService` e `Handler`     | Tentar excluir (`DELETE /generos/{id}`) um gênero que possui livros vinculados dispara `DataIntegrityViolationException` devido ao `ON DELETE RESTRICT` da chave estrangeira.                                                               | Retorna HTTP 500 genérico em vez de informar claramente a regra de negócio ao administrador.                       | Verificar vínculo antes de excluir ou capturar `DataIntegrityViolationException` no `GlobalExceptionHandler` (HTTP 409).  |

## 🟡 Problemas de design / Inconsistências

| Ref | Arquivo                   | Problema                                                                                                                                                                 | Impacto                                                                                                                      | Ação Proposta                                                                                                                |
|-----|---------------------------|--------------------------------------------------------------------------------------------------------------------------------------------------------------------------|------------------------------------------------------------------------------------------------------------------------------|------------------------------------------------------------------------------------------------------------------------------|
| D1  | Controllers               | Rotas mapeadas no singular (ex: `/genero`, `/livro`, `/usuario`, `/aluguel`) em vez do padrão REST no plural.                                                            | Inconsistência no contrato da API REST.                                                                                      | Padronizar todos os `@RequestMapping` no plural (`/generos`, `/livros`, `/usuarios`, `/alugueis`).                          |
| D2  | `application.properties`  | Senha vazia ou fixa em texto plano (`spring.datasource.password=`).                                                                                                      | Ignora variáveis de ambiente configuradas na máquina e expõe credenciais no repositório.                                     | Ajustar para `spring.datasource.password=${SPRING_DATASOURCE_PASSWORD:}` para ler do ambiente com fallback vazio.            |
| D3  | `schema.sql` e `data.sql` | Uso de `spring.sql.init.mode=always` sem scripts idempotentes (`IF NOT EXISTS` / `INSERT IGNORE`). O seed roda a cada inicialização da aplicação.                        | Duplica registros ou quebra o boot local por violação de chave única/estrangeira.                                            | Setar `spring.sql.init.mode=never` após a criação inicial em dev ou tornar os scripts 100% idempotentes.                      |
| D4  | Importações Jackson/Java  | Uso de pacotes legados (`com.fasterxml.jackson.*` ou `javax.*`) no Spring Boot 4.1.2.                                                                                    | Erro de compilação, pois o Spring Boot 4 utiliza exclusivamente Jackson 3 e Jakarta EE 11.                                   | Utilizar estritamente `tools.jackson.*` e `jakarta.*` em todo o projeto.                                                     |

## 🟢 Melhorias e Boas Práticas Ausentes

| Ref | Arquivo                  | Sugestão                                                                                                                                                     | Benefício                                                                                                                                        |
|-----|--------------------------|--------------------------------------------------------------------------------------------------------------------------------------------------------------|--------------------------------------------------------------------------------------------------------------------------------------------------|
| M1  | Todos os Controllers     | Repetição da lógica matemática de paginação (`Math.min(size, 100)` e `page * limit`) em cada Controller.                                                     | Centralizar usando `Pageable` nativo do Spring com `default-page-size=30` e `max-page-size=100` elimina duplicação de código.                    |
| M2  | `GlobalExceptionHandler` | No handler de falha genérica (`Exception.class`), retornar apenas o JSON `"ERRO INTERNO NO SERVIDOR"` sem registrar o erro no console.                        | Adicionar `log.error("Erro interno inesperado", ex)` permite depurar falhas reais em vez de operar às cegas.                                     |
| M3  | Todos os Repositories    | Uso de `SELECT * FROM ...` nas consultas SQL.                                                                                                                | Listar explicitamente as colunas (`SELECT id, generos_id, titulo, autor...`) melhora a performance e evita quebrar `RowMapper`s futuros.         |
| M4  | `Entities` e `Dtos`      | Uso de classes verbosas com getters/setters repetitivos apenas para transportar dados do `JdbcTemplate`.                                                     | Utilizar Java `record`s (nativos no Java 25) torna Entities e DTOs imutáveis, concisos e seguros por padrão.                                     |
